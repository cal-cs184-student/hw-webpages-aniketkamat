Overview

In this homework, I implemented various features to simulate the look and behavior of a cloth in a 3D graphics system. I started by representing it as a mass and spring system before writing code to properly show how it interacts with other materials and itself. I finished by implementing various shading capabilities that I had learned about in prior homeworks. Overall, I better learned how to implement 'physics-based' rules in a computer graphics system. The most challenging and interesting part was definitely part 5 since I had to learn how to use GLSL to efficiently shade the cloth.

In part 1, I implemented the mass and spring system to properly show/compute how the cloth will behave and interact in the simulation.

Part 3: Handling collisions with other objects

For spheres, I check whether the point mass (pm) is inside or on the surface by comparing the distance from the sphere's origin to its radius. If the (pm.position - origin).norm() < radius, I compute the tangent point by projecting the mass radially outward onto the surface: origin + (pm.position - origin).unit() * radius. I then form a correction vector from last_position to that tangent point and set the new position to last_position + (1 - friction) * correction. Intuitively, I check if the point mass in the cloth is inside of the sphere to see where the sphere would have 'pushed' that mass out to. The cloth cannot be inside the sphere, so when they collide, the sphere must push the cloth to outside its surface. For planes, I first check whether there was a crossing by computing the signed distances of last_position and position from the plane using dot(p - point, normal). If their product is negative (or zero), the mass passed through the plane this step. I then calculate the point mass's final position by projecting it perpendicularly onto the plane to get the tangent point and adding the SURFACE_OFFSET along the normal in the direction of whichever side the mass originated on, so the mass lands slightly above the plane rather than exactly on it (this is to prevent artifacts and any issues when calculating the friction effect in the next step). Like above, the new position is last_position + (1 - friction) * correction, so friction damps the tangential velocity. In both cases, a loop is used to check whether each point mass intersects each potential object (ie spheres, planes) and perform the aforementioned procedures if necessary.

Top left, top right, and bottom left show sphere while bottom right shows plane.

As seen above, when the spring constant (ks) increases, the shape of the cloth 'fits' the sphere less. The ks=500 might represent a thin fabric tablecloth where it neatly fits to the shape while the ks=50000 might represent a plastic covering that remains more firm. This is because the cloth at the top of the sphere rests first, so a higher spring constant means that the the point masses at the top 'pull' the other masses towards the top more. Meanwhile, a smaller constant means that they pull the other masses less, so the other masses continue to fall downward. With the plane, the cloth can be seen perfectly at rest and above the plane. No parts are below the plane/going through it and it appears natural.

Part 4: Handling self-collisions

I handle self collissions by using spatial hashing, where I use a hash table and grouping to rapidly check check if point masses are too close to one another (could make cloth go through itself). Specifically, I partition the 3D space into boxes of size w×h×t=3·width/num_width_pointsx3·height/num_height_pointsxmax(w, h), then hash_position truncates a coordinate to its box corner using pos - fmod(pos, w) for all 3 coordinates. I then combine the three truncated values into a single float key using a polynomial hash and at each simulation step, use build_spatial_map to rebuild the hash table from scratch by bucketing every point mass by its current hashed position. In self_collide, I look up the point mass's bucket and for every other mass in it I test whether their separation is less than 2 * thickness. If the separation is less than that, I build a correction vector along (pm.position-other->position).unit() with magnitude 2*thickness - dist that would push them just far enough apart to ensure that the cloth doesn't go through itself (which would be caused by this interaction between nearby point masses otherwise). I then average all such corrections for that mass (excl ones with itself), divide by simulation_steps, and add the result to pm.position which prevents big jumps when lots of masses are in contact at once.
As seen above, the cloth does not pass through itself when it is falling, so the motion appears more realistic. While it is difficult to pinpoint the exact step where a point mass is corrected, the natural/uniform falling shows that there isn't an overcorrection in position either.

In the second row, I varied the spring constant.
